# Glassbox AI I — Transparent Supervised Learning Lab

ニューラルネットワークが入力を受け取り、判断を出し、正解との誤差から全39 Parameterを更新するまでを、実際の数値と数式で追跡するGlassbox AI Iのローカル実験室です。

高性能なAIを作ることは目的にしていません。5入力・4中間・3出力の小さなネットワークを透明な解剖模型として扱い、順伝播、損失、誤差逆伝播、勾配降下の因果関係を一計算ずつ観察できることを優先しています。

## Canonical responsibility

Glassbox AI Iの正本は、固定5→4→3ネットワークの教師あり学習、cross entropy、誤差逆伝播、SGD、139 step数学timelineです。言語モデルは[Glassbox AI II](../glassbox-ai-ii/)、環境報酬から学ぶ強化学習は[Glassbox AI III](../glassbox-ai-iii/)が正本です。

> Legacy compatibility: 分離前のGrid World / REINFORCE code、DOM、testは保存形式と数値回帰のため内部に凍結保持しています。通常UIでは表示せず、新機能の実装先にはしません。

## 基本操作

### Legacy 0. 小型グリッドワールドを使う

第二弾の基本ループは次の通りです。

1. 必要なら「世界シード」を変更し、「世界をリセット」します。
2. 「1. センサーを入力へ送る」で、現在世界から計算した5値をニューラルネット入力へ同期します。
3. 計算ステップ領域の「次のステップ」または「最後まで実行」で順伝播を完了します。
4. 「3. AI判断を世界へ適用」で、argmax出力を前進・左折・右折として一回だけ実行します。
5. 状態遷移、単発報酬、衝突・危険・餌の回数を確認し、次の観測を同期します。

学習させる場合は、手順2の代わりに「2. 教師データを準備」を押します。この操作は現在の5センサーを入力へ送り、壁と危険を避ける安全最短経路の次行動を正解クラスへ設定します。重みはこの時点では変更されません。通常どおり順伝播し、「順伝播後に学習を開始」から既存の139ステップを進めてください。

5センサーは次の値です。すべて`-1`から`+1`の範囲に収めます。

| 入力 | 意味 | 値の読み方 |
|---|---|---|
| `x1` | 前方通行可能 | 前が空きなら`+1`、壁または境界なら`-1` |
| `x2` | 餌方向・前後 | 餌が正面ほど`+1`、背面ほど`-1` |
| `x3` | 餌方向・左右 | 餌が左なら負、右なら正 |
| `x4` | 前方危険度 | 直前が危険なら`+1`、2マス先なら`+0.5`、検出なしは`-1` |
| `x5` | 餌への近さ | マンハッタン距離を`-1`から`+1`へ正規化 |

環境の単発報酬は、空きセルへの前進`-0.01`、左折・右折`-0.02`、壁または境界への衝突`-0.25`、危険セル`-1.00`、餌取得`+1.00`です。これは第二弾では観測用の値であり、SGDの損失や勾配へ混入しません。

### Legacy 0B. 強化学習を観察する

第三弾の基本操作は次の通りです。

1. 報酬プリセット、強化学習シード、割引率`γ`、方策温度`τ`、RL学習率、最大環境ステップを設定します。
2. 「新しいエピソード」で、現在の主ネットワークから固定方策タイムラインを作ります。
3. 「次のRLステップ」で、観測、温度付き方策、乱数サンプリング、環境遷移を一段階ずつ進めます。
4. エピソード終了後は、割引リターン、各遷移の39勾配、平均勾配、39更新へ進みます。
5. 「エピソード最後まで」は同じタイムラインの末尾まで進みます。「前のRLステップ」では世界・経験・部分更新を含むスナップショットを復元します。
6. 完了時だけ、更新後ネットワークと終了世界が第一・第二弾の主表示へ反映されます。

「10エピソード連続」は同じ設定で10回繰り返し、各エピソードの累積報酬、餌、衝突、危険、探索・活用、診断を履歴へ追加します。累積報酬グラフの塗りつぶし点は餌取得ありを示します。

報酬プリセットは次の4種類です。

| プリセット | 目的 |
|---|---|
| 正常 | 餌を正、危険・衝突・無駄な行動を負として目的と報酬を対応させる |
| 疎な報酬 | 餌以外を0にし、成功前に学習信号がない停滞を観察する |
| 衝突ボーナス | 壁への衝突を正報酬にし、報酬設計の失敗を観察する |
| 旋回ボーナス | 左右旋回を正報酬にし、移動せず得点する報酬ハッキングを観察する |

診断は、同じ状態・行動の反復、旋回比率、衝突比率、餌なしの正報酬を検査した候補表示です。AIが意図的に不正を行ったと断定するものではありません。

### 1. 実験条件を決める

1. プリセットまたは5個の入力欄で、`-1.0`から`+1.0`の値を設定します。
2. 必要なら学習率を変更します。初期値は`0.1`です。
3. 正解クラスとして行動A、行動B、行動Cのいずれかを選びます。
4. 同じ初期パラメータを再現したい場合は、同じシードを入力して「完全リセット」を実行します。

プリセットは入力値と正解クラスだけを変更します。現在の重みを学習済み状態へ置き換えることはありません。

### 2. 順伝播を観察する

「次のステップ」を押すたび、次の順序で進みます。

1. 入力値の確定
2. 入力から中間層への20個の積
3. 4個の中間重み付き和とバイアス
4. 4個の`tanh`
5. 中間層から出力層への12個の積
6. 3個のlogitとバイアス
7. softmax
8. argmaxによる判断

初期状態から判断まで46ステップです。各ステップで、計算済みの項は`✓`、現在の項は`▶`、未計算の項は`○`で区別されます。

「前のステップ」は表示だけを戻すのではなく、その時点のネットワーク、途中値、勾配、部分更新状態を含む完全スナップショットへ戻します。「最後まで実行」と自動実行も同じステップ列を進むため、別の計算経路は持ちません。

### 3. 学習を観察する

順伝播の最後まで進むと「順伝播後に学習を開始」が有効になります。学習は次へ分解されます。

1. one-hot変換
2. クロスエントロピー損失
3. 3出力の誤差
4. 出力層12重みの勾配
5. 出力層3バイアスの勾配
6. 4中間ノードへの誤差伝播
7. 4ノードで`tanh`の微分を適用
8. 入力層20重みの勾配
9. 中間層4バイアスの勾配
10. 32重みを一個ずつ更新
11. 7バイアスを一個ずつ更新
12. 更新後ネットワークで再順伝播
13. 学習前後の比較

初期状態から学習前後比較まで139ステップです。更新ステップでは、更新前、勾配、学習率、更新量、更新後を同じ式へ代入して表示します。

### 4. 接続とパラメータを調べる

- 接続線の太さと濃さは重みの絶対値に連動します。
- 正の重みは青系の実線、負の重みは橙系の破線です。
- 現在計算している接続は黄色の太線と`▶`で示します。
- 線へマウスを重ねるかクリックすると、パラメータ名、接続元、接続先、正確な現在値を表示します。
- ノードには入力値、中間層の`z`と`a`、出力層のlogitと確率を併記します。
- パラメータ表は20入力重み、4中間バイアス、12出力重み、3出力バイアスの39行です。

### 5. 自動実行

「再生」で現在位置からステップを自動的に進めます。「一時停止」で止められます。速度は`0.25倍`、`0.5倍`、`1倍`、`2倍`、`4倍`から選べます。

### 6. 3種類のリセット

| 操作 | 重み・バイアス | 計算タイムライン | 直前学習の取消情報 | 操作ログ |
|---|---|---|---|---|
| 計算だけリセット | 現在値を維持 | 推論の先頭へ作り直す | 維持 | 維持 |
| 学習前へ戻す | 直前学習前の39値へ復元 | 推論の先頭へ作り直す | 使用後に消去 | 維持 |
| 完全リセット | 指定シードから再初期化 | 全削除して作り直す | 削除 | 削除 |

タイムライン上の「最初から」は、その履歴の0番スナップショットへ戻る操作です。「計算だけリセット」とは異なり、履歴内で既に起きた更新も含めてその時点の内部状態を復元します。

### 7. 保存・読込・ログ

「状態JSONを保存」は次を保存します。

- 固定ネットワーク構造
- 全重みと全バイアス
- 学習率
- シード
- 5入力
- 正解クラス
- 学習回数

読込時は保存形式名、版、`5-4-3`構造、全配列の形状、有限数、入力範囲、正解範囲を検証します。不正なJSONや別構造のデータは適用前に拒否します。

操作・計算ログは画面で確認でき、TXTまたはJSONとして出力できます。完全リセットだけがログ履歴を削除します。

## ネットワーク構造と記号

- 入力: `x_i`、`i = 1 ... 5`
- 中間ノード: `H_h`、`h = 1 ... 4`
- 出力クラス: `O_o`、`o = 1 ... 3`
- 入力から中間への重み: `W^H_{h,i}`
- 中間バイアス: `b^H_h`
- 中間から出力への重み: `W^O_{o,h}`
- 出力バイアス: `b^O_o`
- 正解one-hot: `y_o`
- 学習率: `η`

実装配列は、`weightsIH[h][i]`と`weightsHO[o][h]`です。UI上の`w_I1_H1`は`weightsIH[0][0]`、`w_H1_O1`は`weightsHO[0][0]`に一意に対応します。

## 順伝播の数式

### 中間層の重み付き和

各中間ノードについて、

```text
z^H_h = Σ_i W^H_{h,i} x_i + b^H_h
```

実装した固定構造では、

```text
z^H_h =
  W^H_{h,1} x_1
+ W^H_{h,2} x_2
+ W^H_{h,3} x_3
+ W^H_{h,4} x_4
+ W^H_{h,5} x_5
+ b^H_h
```

です。

### tanh活性化

```text
a^H_h = tanh(z^H_h)
          e^(z^H_h) - e^(-z^H_h)
        = -------------------------
          e^(z^H_h) + e^(-z^H_h)
```

JavaScriptでは`Math.tanh`を使用します。出力範囲は`-1`から`+1`です。

### 出力層のlogit

```text
l_o = Σ_h W^O_{o,h} a^H_h + b^O_o
```

固定構造では、

```text
l_o =
  W^O_{o,1} a^H_1
+ W^O_{o,2} a^H_2
+ W^O_{o,3} a^H_3
+ W^O_{o,4} a^H_4
+ b^O_o
```

です。logitは確率化前の生の得点です。

## softmaxの数式

通常の定義は、

```text
p_o = exp(l_o) / Σ_k exp(l_k)
```

です。実装では指数の桁あふれを防ぐため、`m = max(l_1, l_2, l_3)`を引きます。

```text
p_o = exp(l_o - m) / Σ_k exp(l_k - m)
```

全logitから同じ定数を引いても確率は変わりません。これにより、極端に大きいlogitでも`Infinity / Infinity`を避けられます。3確率は0以上で、合計は浮動小数点誤差の範囲内で1になります。

選択された判断は確率的サンプリングではなく、

```text
selected = argmax_o(p_o)
```

です。同率の場合は実装上、先に現れたクラスを選びます。

## REINFORCE方策勾配

第三弾では、通常のlogit `l_o`を方策温度`τ > 0`で割って確率方策を作ります。

```text
q_o = exp(l_o / τ) / Σ_k exp(l_k / τ)
```

実装では通常のsoftmaxと同様、`l_o / τ`の最大値を引いて数値安定化します。`τ`が大きいほど確率分布は一様に近づき、小さいほど最大logitの行動へ集中します。

行動はシード付き乱数`u ∈ [0,1)`が入る累積確率区間から選びます。選択行動が`argmax(q)`と同じなら活用、異なれば探索として記録します。これは表示上だけの分類で、どちらも同じ確率方策から生成された有効な経験です。

エピソード終了後、割引リターンを終端から逆順に求めます。

```text
G_t = r_t + γ G_(t+1)
```

各遷移の方策損失は次です。

```text
L_t = -G_t log q(a_t | s_t; τ)
```

元のlogitに対する微分は、選択行動のone-hotを`y`として、

```text
∂L_t / ∂l_o = (G_t / τ) (q_o - y_o)
```

です。正の`G_t`は勾配降下によって選択行動確率を上げ、負の`G_t`は下げます。この出力deltaから、第一弾と同じ全結合と`tanh`の連鎖律で全39パラメータの勾配を求めます。

`T`遷移の勾配を平均し、第三弾専用学習率`η_RL`で更新します。

```text
g = (1 / T) Σ_t ∇L_t
θ_new = θ_old - η_RL g
```

第三弾初版はベースライン、Advantage正規化、エントロピー正則化を使用しません。リターンの符号と更新方向を直接追跡できる単純性を優先しています。

## クロスエントロピー損失

one-hot教師`y`に対する損失は、

```text
L = -Σ_o y_o log(p_o)
```

です。one-hotでは正解クラス`t`だけが1なので、

```text
L = -log(p_t)
```

と同じです。`log(0)`を避けるため、実装では正解確率の下限に`Number.EPSILON`を使用します。

## 誤差逆伝播

softmaxとクロスエントロピーを組み合わせると、各logitに対する損失の微分は、

```text
δ^O_o = ∂L/∂l_o = p_o - y_o
```

です。

出力層の重みとバイアスの勾配は、

```text
∂L/∂W^O_{o,h} = δ^O_o a^H_h
∂L/∂b^O_o     = δ^O_o
```

です。

中間ノードへ、更新前の出力層重みを使って誤差を伝えます。

```text
e^H_h = Σ_o W^O_{o,h} δ^O_o
```

`tanh`の微分は活性値から計算できます。

```text
d tanh(z^H_h) / dz^H_h = 1 - (a^H_h)^2
```

したがって、中間層の重み付き和に対するdeltaは、

```text
δ^H_h = e^H_h [1 - (a^H_h)^2]
```

入力層側の重みと中間バイアスの勾配は、

```text
∂L/∂W^H_{h,i} = δ^H_h x_i
∂L/∂b^H_h     = δ^H_h
```

です。

## 重みとバイアスの更新

全39パラメータ`θ`に同じSGD更新式を適用します。

```text
θ_new = θ_old - η ∂L/∂θ
```

UIで表示する更新量は、

```text
update = -η ∂L/∂θ
θ_new  = θ_old + update
```

です。勾配を求める間は更新前ネットワークを固定し、全勾配が揃ってから一個ずつ更新します。UIで部分更新中の状態へ戻った場合は、その時点まで更新済みのパラメータだけを持つスナップショットが復元されます。

通常の小さい正の学習率では、一回の勾配降下により同じ入力の損失は減ります。ただし、極端に大きい学習率や浮動小数点の限界では増える可能性があるため、UIは結果を検査して「損失は減少」または「損失は非減少」をそのまま表示します。

## シードによる再現性

シード文字列をFNV-1a形式の32bitハッシュへ変換し、Mulberry32系の自前疑似乱数生成器へ渡しています。入力から中間への20重み、中間4バイアス、中間から出力への12重み、出力3バイアスを常に同じ順序で生成します。

- 重みの初期範囲: `[-0.45, +0.45)`
- バイアスの初期範囲: `[-0.10, +0.10)`

同じ実装版、同じシードでは39個すべてが同じ値になります。`Math.random()`には依存しません。

## 表示精度

2桁、4桁、6桁を切り替えられます。`toFixed`による丸めはDOMへ表示する時だけです。順伝播、逆伝播、保存、スナップショット、勾配チェックは丸め前のJavaScript数値を使用します。

## 勾配チェック

各パラメータ`θ_j`について中央差分を使います。

```text
g_numeric_j = [L(θ_j + ε) - L(θ_j - ε)] / (2ε)
```

設定は次の通りです。

- `ε = 1e-5`
- 許容する正規化誤差: `1e-5`未満
- 正規化誤差: `|g_numeric - g_analytic| / max(1, |g_numeric|, |g_analytic|)`

中央差分は前進差分より打切り誤差が小さく、`ε = 1e-5`は倍精度数値で打切り誤差と丸め誤差の均衡を取りやすい値です。分母を最低1にすることで、真の勾配が0付近の時に相対誤差だけが不自然に増えることを避けます。`1e-5`はこの小型で滑らかなネットワークに対して十分厳しく、実装ミスを検出しつつ倍精度のノイズを許容する基準です。

検証時の固定ケースでは、全39パラメータが合格し、最大正規化誤差は約`1.64e-11`でした。

REINFORCE方策損失についても、温度`1.4`、リターン`0.73`の固定ケースで全39パラメータを同じ中央差分条件へ通しています。検証時の最大正規化誤差は`1.57216184515363e-11`でした。

## 既知の制限

- ネットワーク構造は`5-4-3`に固定されています。
- 学習は一件の入力に対する一回のSGD更新で、データセット、ミニバッチ、検証データはありません。
- 「学習回数」は教師あり単一サンプル更新またはREINFORCEエピソード更新を主ネットワークへ反映した回数です。一般的なデータセットのエポックとは同じ意味ではありません。
- 更新後の再順伝播は学習段階の一ステップとして完全な順伝播結果を表示します。更新後の各積をもう一度接続単位で展開したい場合は、「計算だけリセット」から通常の推論ステップを進めます。
- スナップショットは理解しやすさを優先して完全コピーを保持します。大規模ネットワークへそのまま拡張する設計ではありません。
- JSON保存はネットワーク状態を保存します。計算タイムラインや画面ログは状態JSONへ含めません。ログは別途TXT/JSONで出力します。
- 世界状態はネットワーク状態JSONに含めません。世界は独立した「世界シード」と「世界をリセット」で再現します。
- グリッドは7×7の固定マップで、壁と危険の配置は固定です。開始方向と餌位置だけを世界シードから選びます。
- 第二弾の安全最短経路教師は、現在位置・向き・固定障害物を知るコード所有の教師です。ネットワーク自身が探索して獲得した知識ではありません。
- 第二弾パネルの単発報酬は表示とログだけに使います。第三弾パネルでは、選択した報酬プリセットの値を割引リターンと方策勾配へ実際に使用します。
- 第三弾はREINFORCEだけを実装しています。Q値、価値関数、Actor-Critic、経験再生、ターゲットネットワークはありません。
- REINFORCEは分散が大きく、単一エピソードの累積報酬が毎回改善する保証はありません。第三弾初版はベースラインやAdvantage正規化を使いません。
- 探索・活用は、確率サンプリング行動がargmaxと一致したかで分類します。別のε-greedy方策は使いません。
- 報酬ハッキング等の診断は観測条件に基づく候補です。AIの意図、理解、目的を推定しません。
- RLエピソード履歴と途中タイムラインは状態JSONに含めません。完了して主ネットワークへ反映された39パラメータは既存形式で保存できます。
- ブラウザのファイルダウンロード許可設定によっては、保存時にブラウザ側の確認が表示される場合があります。
- 浮動小数点はJavaScriptの倍精度です。厳密な有理数計算ではありません。

### 初心者向けの学習経路

三つの実験を、同じものとしてではなく、共通する因果鎖と異なる学習信号の両方から観察します。

1. 第一弾の教師あり学習では、人間が指定した正解ラベルと予測の差が学習信号です。
2. 第二・第三弾の環境実験では、行動後に環境から返る報酬と、時間をまたぐ割引リターンが学習信号です。
3. Glassbox AI IIの言語モデルでは、次に実際に現れたTokenが教師であり、次Token予測誤差が学習信号です。

すべてに「入力 → パラメータを使った計算 → 確率 → 学習信号 → 勾配 → 更新」という共通骨格があります。一方、強化学習そのものを生成AIや言語モデルと同一視しません。生成AIへつながる理解は、確率分布とパラメータ更新という共通骨格を確認したうえで、Transformer固有のToken、Embedding、Attention、次Token予測へ進みます。
