# Glassbox AI 初版 実装計画

## 1. 目的と完成像

5入力・4中間・3出力の極小ニューラルネットワークについて、入力から判断、損失、誤差逆伝播、全39パラメータの更新、更新後の判断変化までを、実際の数値と数式に結び付けて観察できるローカル実験室を作る。

性能や応用範囲は広げず、単一サンプルに対する一回のSGD学習を完全に追跡できることを初版の成功条件とする。

## 2. 技術方針

- HTML / CSS / Vanilla JavaScript / ES Modules / SVGのみでブラウザUIを構成する。
- 学習済みモデル、OpenAI API、外部API、機械学習ライブラリ、UIフレームワーク、CDNは使用しない。
- ビルド工程は設けず、`python -m http.server 8000` で配信する。
- 数学コアはDOMを参照せず、Node.js標準テストランナーから直接検証可能にする。
- 内部計算はJavaScriptの倍精度数値を保持し、丸めはUI描画時だけ行う。

## 3. 数学コア

1. シード付き疑似乱数生成器で32個の重みと7個のバイアスを再現可能に初期化する。
2. `tanh`中間層、数値安定化した`softmax`出力層の順伝播を実装する。
3. one-hot正解とクロスエントロピー損失を実装する。
4. `softmax + cross entropy`の出力誤差から、全39パラメータの解析勾配を求める。
5. 単純SGDの更新と、更新前後の比較統計を実装する。
6. 中央差分による全パラメータの勾配チェックを実装する。

## 4. ステップエンジン

- 推論は入力確定、20個の入力積、4個の中間和、4個の`tanh`、12個の出力積、3個のlogit、softmax、argmaxへ分解する。
- 学習はone-hot、損失、出力誤差、出力層勾配、中間層伝播、`tanh`微分、入力層勾配、32個の重み更新、7個のバイアス更新、更新後順伝播、比較へ分解する。
- ステップごとに完全な状態スナップショットを保存し、前後移動時に内部状態と表示状態を同時に戻す。
- 一括実行と自動実行も、同じステップ列を進めることで結果の分岐を防ぐ。

## 5. UIと可視化

- 入力、実験設定、ネットワークSVG、計算式、自然言語説明、学習、比較、全パラメータ表、ログを分離したパネルにする。
- SVG接続線は符号を色と実線・破線、絶対値を太さと濃さで示す。
- ノードは実際の入力値、中間層の重み付き和、活性値、logit、確率を表示する。
- 接続のホバー・クリック、現在接続の強調、パラメータ表の現在行強調を同じ識別子で連動させる。
- 重要状態は色だけに依存せず、記号、線種、ラベル、文字でも示す。

## 6. 状態管理と入出力

- 学習率、シード、入力、正解、学習回数、構造、全重み・バイアスをJSON保存する。
- 読み込み時は版、固定構造、配列形状、有限数、入力範囲、正解範囲を検証し、不正データを拒否する。
- 計算だけリセット、直前学習の取消、完全リセットを異なる処理として実装する。
- ログはテキストとJSONの両形式でダウンロード可能にする。

## 7. テストと完了判定

- Node.js標準テストで、指定された10項目をすべて確認する。
- 勾配チェックは中央差分 `ε = 1e-5` を使い、正規化誤差 `1e-5` 未満を基準にする。
- `python -m http.server 8000` で配信し、実ブラウザで次を確認する。
  - 5・4・3ノードと32接続、全39パラメータ行
  - 入力同期、推論ステップ前後移動、最後まで実行
  - 学習ステップ、更新後比較、学習取消
  - プリセット、精度切替、再生・停止・速度
  - JSON保存、ログ出力、無効読込拒否
  - 画面幅を狭めた際の最低限の操作性
- 実装後にREADME、Issue、PRのいずれかへ結果と残課題を追跡可能に記録する。

## 8. 第二弾：小型グリッドワールド

### 8.1 目的

第一弾の5入力・3出力ネットワークを、7×7の小さな環境へ接続する。環境の状態が5個の実数へ変換され、その入力から得たargmax行動が世界をどう変えるかを観察可能にする。

### 8.2 第三弾との境界

- 第二弾は環境状態、センサー、行動、単発報酬、教師ラベルを実装する。
- 報酬は遷移結果の観察値であり、重み更新へ直接使わない。
- 学習は安全最短経路の教師ラベルを使う第一弾の教師ありSGDとする。
- 累積報酬、探索、方策更新、Q値は第三弾で別設計する。

### 8.3 環境モデル

- 7×7、固定内部壁、危険セル、餌、位置と向きを持つエージェント。
- 行動Aを前進、行動Bを左折、行動Cを右折へ対応させる。
- 世界シードから初期向きと餌位置を決定的に生成する。
- 壁・境界は移動を拒否し、危険は移動を許可して負の単発報酬、餌は取得して正の単発報酬を返す。
- 餌取得後は、同じシードと取得回数から次の餌を再現可能に選ぶ。

### 8.4 5入力

1. 前方通行可能性
2. 餌方向の前後成分
3. 餌方向の左右成分
4. 前方危険度
5. 餌への近さ

全値を`[-1,+1]`へ収め、センサー表の実値と第一弾入力欄を一致させる。

### 8.5 教師

- 位置・向きを含む状態空間で幅優先探索する。
- 危険、壁、境界を通らない最短行動列を求める。
- 最初の行動だけをone-hot教師ラベルとして第一弾へ渡す。
- 教師データ準備時には重みを更新せず、利用者が既存ステップ学習を開始するまで状態を固定する。

### 8.6 UI

- グリッド、セル凡例、方向、単発報酬、イベント、カウンタを表示する。
- 5センサーの名前、範囲内実値、意味を表示する。
- センサー同期状態を明示し、世界遷移後や手動入力後は未同期へ戻す。
- センサー送信、教師データ準備、AI判断適用、世界リセットを別操作にする。
- 強化学習ではないことをパネル内へ明記する。

### 8.7 完了判定

- 同じ世界シードで同じ初期状態を再現する。
- 餌、壁、危険、向きが7×7グリッドへ表示される。
- 5センサーが第一弾入力と数値一致する。
- 推論完了後のargmax行動だけを世界へ適用できる。
- 世界遷移後にセンサー未同期が明示される。
- 教師行動を既存正解ラベルへ反映し、可視化付きSGDで学習できる。
- 教師経路が壁・危険を避けて餌へ到達する。
- 第一弾回帰テスト、第二弾テスト、勾配チェックがすべて成功する。
- 実ブラウザで主要フロー、狭幅表示、コンソールエラーを確認する。

## 9. 第三弾：強化学習の可視化

### 9.1 目的

第二弾の環境で得た報酬を、実際のニューラルネットワーク更新へ結び付ける。状態、確率方策、サンプリング、環境遷移、単発報酬、割引リターン、方策勾配、39パラメータ更新を別々に停止・復元できるようにする。

### 9.2 学習方式

- 温度付きsoftmaxを確率方策とするエピソード型REINFORCEを自前実装する。
- 行動はシード付き疑似乱数で確率的に選び、argmax一致を活用、不一致を探索として記録する。
- 割引リターン`G_t = r_t + γG_(t+1)`を逆順に求める。
- 方策損失`L_t = -G_t log q(a_t|s_t;τ)`から全39解析勾配を求める。
- エピソード平均勾配を単純SGDで一回適用する。

### 9.3 観察タイムライン

- 各環境時刻を観測、方策、サンプリング、遷移へ分解する。
- 終了後にリターン、遷移別勾配、平均勾配、39更新、比較へ分解する。
- 各段階の世界、ネットワーク、経験、勾配、部分更新を完全スナップショットとして持つ。
- 前のステップ、次のステップ、最後まで実行を同じステップ列へ適用する。

### 9.4 報酬設計実験

- 正常、疎な餌報酬、衝突ボーナス、旋回ボーナスを切り替える。
- 累積報酬と餌取得を別々に表示する。
- 反復状態、衝突比率、旋回比率、餌なし正報酬から、局所最適・設計失敗・報酬ハッキング候補を診断する。
- 診断は観測条件を表示し、AIの意図を断定しない。

### 9.5 UI

- 第三弾専用グリッド、設定、操作、現在式、方策確率、乱数区間、統計、診断を表示する。
- エピソード履歴を累積報酬と餌取得の双方で比較する。
- 全39パラメータについて現在値、平均方策勾配、更新量、更新後を表示する。
- 単一エピソードの段階実行と10エピソード連続実行を用意する。

### 9.6 完了判定

- 温度付き確率の合計が1で、同じシードから同じサンプリング列を再現する。
- 正負のリターンが選択行動確率をそれぞれ増減させる。
- 方策勾配の全39数値勾配チェックが通る。
- ステップ実行と一括実行の最終世界・ネットワークが一致する。
- 前のステップで世界、経験、勾配、部分更新を復元する。
- 4報酬プリセットと診断が実際の遷移値に連動する。
- 第一・第二弾を含む全回帰テストが成功する。
- 実ブラウザで単一・連続学習、主ネットワーク反映、狭幅表示、コンソールエラーを確認する。

## 10. 第三弾の教材・OSS品質強化

### 10.1 現行実装を正本にする

- v3のREINFORCE数学処理と139ステップ教師ありタイムラインを作り直さない。
- 第三弾専用`ReinforcementStepEngine`を別軸として維持する。
- 既存保存JSONとの互換性を維持し、RL履歴は別形式で出力する。

### 10.2 環境履歴を完全化する

- 各経験へ遷移前/後の世界snapshotと、その時点の累積報酬を保存する。
- 表で状態、行動、探索/活用、イベント、報酬、累積報酬、割引リターンを同時に追えるようにする。
- エピソード完了記録を専用JSONとしてexportし、構造、有限値、件数対応を検証する。

### 10.3 二つの時間軸を明示する

- 教師あり139ステップは「ネットワーク内部の数式順序」。
- RL専用軸は「環境時刻とcredit assignment」。
- RL因果レールは観測、方策、サンプリング、遷移/報酬、リターン、勾配、更新、比較を表示する。

### 10.4 初心者向け学習経路

- 共通骨格を「入力→内部表現→確率→学習信号→勾配→更新」と示す。
- 教師あり、強化学習、次Token予測の学習信号の違いを短く明記する。
- 強化学習だけを生成AIの仕組み全体として誤認させない。

### 10.5 OSS保守基盤

- Node標準テストだけで再現可能な`npm run check`とGitHub Actions CIを用意する。
- CONTRIBUTINGとSECURITYへ変更境界、検証方法、脆弱性報告方法を記載する。
- 公開実績や採用実績を捏造せず、LICENSE、公開repository、maintainer運用は残課題として分離する。
